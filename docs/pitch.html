CQA — оценка качества диалогов

ИИ проверяет каждый чат и звонок оператора по чек-листу и объясняет каждую оценку репликой из диалога.

Команда astanait · Bakdaulet Dagystanov, Ризат

Проблема

  • Контроль качества слушает 1–3% диалогов вручную, остальное — слепая зона.
  • Оценка субъективна, оператору трудно её оспорить.
  • Три языка — RU, KZ, EN — и два канала: чаты и звонки.

Что мы сделали

Оценка 100% диалогов

8 критериев, веса, N/A с перераспределением, флаг грубых ошибок — всё по чек-листу организаторов, арифметика в коде, не в модели.

Доказательства

По каждому критерию: ответ, баллы, объяснение и ссылка на реплику. Для звонков — переход к моменту записи и метрики пауз.

Апелляция

Оператор оспаривает критерий, проверяющий подтверждает или меняет оценку с причиной, итог пересчитывается, история хранится.

Гибкие чек-листы

Редактор критериев с версиями: отдельные чек-листы для чатов и звонков, новая версия применяется в один клик.

Модель: локально, без утечки данных

$0

за оценку: Gemma 4 31B работает на обычном ноутбуке через Ollama. Диалоги клиентов не покидают контур компании.

52 с

на чат, 100 с на звонок. Быстрый режим Qwen 3.6 — 15 с. Внешние API (Claude, Gemini) подключаются переключателем, если нужны.

Через внешний API 100 000 чатов в месяц стоили бы $2 200–4 400. Локально — только электричество.

Демо

  • Диалог и его оценка: баллы, объяснение, клик → реплика
  • Пример N/A и как перераспределился вес
  • Апелляция оператора → решение проверяющего → новый итог
  • Меняем критерий в чек-листе → новая версия → оценка заново

Архитектура

  • Интерфейс: HTML/CSS/JS без фреймворков, один компонент — переносится в Dynamics 365.
  • Сервер: Python, JSON API, журнал действий. Хранение — файлы, легко заменить на БД.
  • Модель: только классифицирует и указывает реплики; баллы, веса, N/A и округление — детерминированный код с тестами.
  • Строгий формат ответа модели с валидацией и повтором при ошибке — 0 сбоев на 75 диалогах.
