# CQA — Conversation Quality Analytics

Прототип для хакатона Freedom Broker / Data Challenge'26: автоматическая оценка работы оператора
в чатах и звонках (RU / KZ / EN) по настраиваемому чек-листу — с обоснованием, ссылкой на реплику,
апелляцией, решением проверяющего и выгрузкой результатов в формате организаторов.

## Запуск (2 минуты)

Нужен только Python 3.9+ (на macOS уже есть). Сервер и интерфейс — без фреймворков и сборки.

```bash
git clone https://github.com/Dxpeare/cqa-hackathon.git
cd cqa-hackathon
python3 -m pip install --user -r requirements.txt      # только пакет anthropic
cp .env.example .env                                   # впишите ANTHROPIC_API_KEY и CQA_API_URL
python3 server.py                                      # http://localhost:8080
```

Без ключа API сервер тоже запускается: в «Настройках» выберите «Демо без ИИ» —
интерфейс, апелляции, чек-листы и выгрузка работают, а оценки ставит простая эвристика.

Windows: `py -m pip install --user -r requirements.txt`, затем `py server.py`.

## Что умеет

| Контур | Что есть |
|---|---|
| Чек-листы | Редактор: критерии, формулировки, вес, тип (Да/Нет или шкала), N/A и его условие, секции. Каждое сохранение — новая версия; старые оценки хранят свою версию чек-листа. Отдельные чек-листы для чатов и звонков. |
| Оценка | Загрузка диалогов (JSON или GET-API организаторов), выбор чек-листа, оценка одним кликом или всего набора. Модель только классифицирует критерии и указывает реплики-доказательства; баллы, перераспределение веса при N/A и округление считает код. |
| Результат | По каждому критерию: ответ, баллы, вес, обоснование, уверенность, кнопки-ссылки на реплики (подсветка и прокрутка), проверенный участок для пропущенного действия, причина N/A. Итог, результаты секций, флаг грубой ошибки. Для звонков — плеер записи с переходом к моменту реплики и метрики пауз/темпа по меткам времени. |
| Апелляция | Оператор выбирает критерий и оставляет комментарий. Проверяющий (переключатель роли в карточке) подтверждает или меняет оценку с указанием причины; итог пересчитывается, в карточке видны исходная оценка, решение и финальный результат. |
| Сдача | `results/dev/results.json`, `results/prod/results.json` в формате JSON 1.0 организаторов (+ `results_detailed.json` с полными данными). Встроенная проверка: все ID, без дублей, по 8 критериев, ошибки не скрываются (`status: "error"`). |

## Модель и стоимость

Провайдер выбирается в «Настройках»:

| Режим | Модель | ≈ стоимость одной оценки | Когда |
|---|---|---|---|
| Claude API (по умолчанию) | `claude-opus-5-5` | чат $0.06–0.10, звонок $0.12–0.20 | основной режим, лучшее качество, особенно KZ |
| Claude API | `claude-sonnet-5-5` / `claude-haiku-5-5` | $0.03–0.05 / <$0.01 | дешевле; haiku — для быстрых прогонов |
| Локальная (Ollama) | напр. `qwen3:32b` | $0, 1–3 мин на чат | без интернета и без оплаты |
| Гибрид | локальная + Claude | между | KZ, звонки и неуверенные ответы локальной модели уходят в Claude |

Фактическая стоимость каждой оценки считается по реальному числу токенов и показана в карточке и в
`results_detailed.json`. Ответ модели запрашивается по строгой JSON-схеме и проверяется кодом
(разрешённые ответы, границы индексов реплик); при ошибке — один повторный запрос с перечнем ошибок.

## Контрольный час (prod)

```bash
python3 scripts/run.py all <GROUP_ID> --folder prod    # скачать из API → оценить → results/prod/results.json
git add results && git commit -m "prod results" && git push
```

Команда печатает прогресс, ошибки по диалогам и проверку формата. Повторный запуск оценивает только
неоценённые диалоги (`--force` — заново). То же можно сделать из интерфейса: «Скачать из API…» →
«Оценить все неоценённые» → «Выгрузить results.json».

## Структура

```
server.py            HTTP-сервер и JSON API (stdlib)
cqa/scoring.py       правила подсчёта баллов (веса, N/A, округление) + тесты в tests/
cqa/evaluator.py     промпт, вызов модели (Claude / Ollama / гибрид / демо), валидация ответа
cqa/storage.py       датасеты, версии чек-листов, оценки, апелляции (JSON-файлы)
cqa/batch.py         пакетная оценка, загрузка из API, экспорт results.json
web/                 интерфейс (HTML + CSS + JS, всё внутри #cqa-app — переносимо в Dynamics 365)
checklists/          чек-листы (chat_v1.json — из PDF организаторов; call_v1.json — для звонков)
data/                наборы диалогов   results/   выгрузки   storage/   оценки и апелляции (не в git)
```

Тесты правил подсчёта: `python3 -m unittest discover -s tests`.
